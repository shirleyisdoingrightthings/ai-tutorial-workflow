# Quiz Skill · AI Tutorial

> 激活条件：
> - **被动**：用户说「测验」「Quiz」「考考我」「巩固一下」时加载此文件
> - **主动**：在完成一个概念的完整讲解并保存笔记之后，AI 在回复末尾附加询问：
>   > 💡 笔记已保存——要不要做一道小测验，检验你的理解？

---

## 题型设计（三种）

| 题型 | 考察目标 | 适用场景 |
|---|---|---|
| **回忆型** | 能否用自己的话复述核心定义 | 概念初学，刚讲完一个新术语 |
| **应用型** | 能否识别概念在真实案例中的体现 | 概念有了基础认知，进入内化阶段 |
| **场景判断型** | 能否在具体情境中做出正确决策 | 概念较为复杂，有多个变体或边界条件 |

---

## 执行流程

### 第一步：选题

根据当前讨论的概念和用户的学习深度，选择最合适的题型（优先应用型 > 场景判断型 > 回忆型）。

**一次只出一道题**——给出题目后等待用户回答，不提前透露参考答案或提示。

### 第二步：出题格式

```
🧠 **Quiz · [{概念名称}]**

**[题型：回忆型 / 应用型 / 场景判断型]**

{题目正文}

（可附选项 A/B/C/D，也可为开放式问答——根据题型选择）
```

### 第三步：等待回答

用户作答后，给出反馈：

```
**你的理解：**[一句话点评，直接、有立场]

**参考答案：**[简洁版正确说法]

**关键点：**[答对了哪里；如果答错，错在哪个认知节点上]
```

反馈原则：
- 对的地方直接说"对了"，不要过度夸奖
- 错的地方直接指出错误所在，不要委婉绕圈
- 点评聚焦在认知节点，而不是措辞是否精确

### 第四步：追问（按需）

如果用户的回答揭示了深层疑问，或者答对了但可能只是猜对的，可以追加一道：

> 不错！延伸一问：{更深一层的问题}

**每个概念最多追问一次**，避免测验变成审问。

## 三种题型示例

### 回忆型示例（Harness Engineering）

> 用你自己的话解释：「Harness」指的是什么？它和 Model 是什么关系？

---

### 应用型示例（Progressive Disclosure）

> 以下哪个设计更符合 Progressive Disclosure 原则？
>
> A. 启动时一次性把所有规则加载进 Context Window  
> B. CLAUDE.md 只保留入口规则，详细规则分散在 skills/ 文件夹按需加载  
> C. 把所有规则写在一个 README，需要时用 Ctrl+F 查找  
> D. 用注释把不常用规则标记为「低优先级」但仍然全部加载

---

### 场景判断型示例（Dumb Zone）

> 你正在用 Claude Code 处理一个大型文档分析任务，运行了一段时间后发现模型的输出质量开始变差——回答变得机械、不再主动推断上下文。
>
> 根据 Dumb Zone 原理，你最可能的诊断是什么？你会采取什么干预措施？

## Quiz 记录（追加到当前概念笔记）

完成测验后，将结果追加写入对应笔记文件的末尾：

```markdown
---

## Quiz 记录

**日期**：YYYY-MM-DD
**题型**：[回忆型 / 应用型 / 场景判断型]
**题目**：[题目原文]
**作答情况**：[正确 / 部分正确 / 错误]
**暴露的认知盲点**：[如果答错，记录错误在哪个节点；答对则留空]
```

如果当前概念尚无对应笔记，询问用户是否先保存笔记，再进行测验。

---

## 元规则

- Quiz 只服务于概念巩固，不评分、不排名
- 题目难度要略高于「刚好能答上来」——目标是暴露认知盲点，而不是让用户轻松过关
- 如果用户明显已经掌握，不重复出相同层级的题，直接升级到更深一层
